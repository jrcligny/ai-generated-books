# Chapitre 4. Préparer les données et construire les variables

La somme du Chapitre 2 et la descente du Chapitre 3 supposent des nombres déjà comparables, sans trou et sans catégorie brute. Une table réelle n'est pas dans cet état. Le temps de construction d'un modèle passe d'abord là : une valeur absente, une modalité qui apparaîtra seulement à l'appel, une colonne dont l'unité écrase les autres. Si la transformation calculée au service n'est pas celle de l'entraînement, le modèle que vous appelez n'est plus celui que vous avez mesuré.

## Objectifs

- Imputer une valeur manquante avec une statistique apprise sur l'entraînement seul
- Encoder une catégorie sans utiliser la cible
- Standardiser avec les statistiques de l'entraînement, et relire les coefficients du Chapitre 2
- Repérer une transformation qui fuirait si on l'ajustait sur toute la table

## Ce qu'une table brute empêche

Trois défauts reviennent. Une case vide : le calcul de la droite n'accepte pas un trou. Une catégorie, « a », « b » ou « c » : une somme pondérée attend un nombre. Une colonne en centaines à côté d'une colonne en unités : le Chapitre 3 a montré qu'un pas raisonnable explose, et le Chapitre 2 que les coefficients ne se comparent plus.

Préparer, ce n'est pas embellir le fichier. C'est fixer une transformation, l'apprendre sur les lignes d'entraînement, et la réappliquer telles quelles aux lignes nouvelles. La statistique qui sert à boucher un trou ou à centrer une colonne fait partie du modèle, au même titre que w et b.

## Valeurs manquantes

*Imputer*, c'est remplacer une case vide par une valeur. La plus simple est la moyenne des cases connues. Cette moyenne doit être celle de l'entraînement. Si l'on y mêle une ligne extrême réservée à plus tard, ou toute la table, le nombre qui bouche le trou dépend de données que l'appel n'aura pas, ou qu'il ne doit pas voir.

L'Exemple 4-1 oppose les deux moyennes sur cinq nombres, dont le dernier est un extrême tenu à l'écart.

*Exemple 4-1. La moyenne d'imputation dépend des lignes qu'on lui donne*

```python
import numpy as np

valeurs = np.array([1.0, 2.0, 4.0, 5.0, 100.0])
moyenne_train = valeurs[:4].mean()
moyenne_tout = valeurs.mean()
print(f"{moyenne_train:.1f}")
print(f"{moyenne_tout:.1f}")
```

La sortie est :

```
3.0
22.4
```

Une case vide bouchée par 3 reste dans l'échelle des quatre premières mesures. Bouchée par 22,4, elle est tirée par le 100 que l'on avait mis de côté. Le modèle apprend alors un centre qui n'existera pas quand cette valeur extrême sera absente.

> **Warning**
>
> Recalculer la moyenne à chaque appel, sur les lignes du moment, change le modèle en silence. La transformation se fige à l'entraînement, puis s'applique telle quelle.

## Catégories

Une modalité n'est pas un nombre. Lui donner 1, 2 et 3 invente un ordre et des écarts : « c » serait trois fois « a ». L'*encodage one-hot* (*one-hot encoding*) crée une colonne par modalité, valant 1 si l'exemple porte cette modalité, 0 sinon. Aucune colonne n'est « plus grande » qu'une autre.

L'Exemple 4-2 encode quatre mentions de trois modalités.

*Exemple 4-2. Trois modalités, trois colonnes*

```python
import numpy as np
from sklearn.preprocessing import OneHotEncoder

cats = np.array(["a", "b", "c", "a"]).reshape(-1, 1)
enc = OneHotEncoder(sparse_output=False)
codes = enc.fit_transform(cats)
print(codes.astype(int))
```

La sortie est :

```
[[1 0 0]
 [0 1 0]
 [0 0 1]
 [1 0 0]]
```

La quatrième ligne répète la première : « a » retrouve la même colonne. Une modalité absente de l'entraînement n'a pas de colonne. À l'appel, elle ne peut pas être inventée. Le geste honnête est de la refuser, ou de la rabattre sur une modalité « autre » prévue dès l'entraînement.

Ces colonnes sont creuses : beaucoup de zéros dès que les modalités se comptent par centaines. Le Chapitre 15 remplacera ce vecteur creux par un vecteur court appris. Ici, le one-hot suffit, et il n'utilise pas la cible.

> **Note**
>
> Coder une modalité par la moyenne de la cible parmi les lignes qui la portent s'appelle un encodage par la cible. La colonne contient alors la réponse. C'est une fuite, au sens du Chapitre 1. Le Chapitre 7 en mesure le chiffre. Ce livre ne l'enseigne pas comme une technique à appliquer.

## Échelle

Reprenons l'idée du Chapitre 2 : deux variables qui portent un effet comparable, écrites dans des unités très différentes. Ici, la seconde est dispersée sur une échelle d'environ 100, et son coefficient brut est près de 100 fois plus petit. Après *standardisation* (*standardization*), chaque colonne est centrée sur sa moyenne d'entraînement et divisée par son écart-type d'entraînement. Un coefficient se lit alors comme l'effet d'un écart-type, et deux coefficients redeviennent comparables.

L'Exemple 4-3 ajuste la même cible avant et après cette transformation. Les moyennes et les écarts-types viennent des quatre-vingts lignes, qui jouent ici le rôle de l'entraînement tout entier.

*Exemple 4-3. Coefficients bruts, puis par écart-type*

```python
import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
n = 80
x1 = rng.normal(0, 1, n)
x2 = rng.normal(0, 100, n)
y = 2 * x1 + 0.02 * x2 + rng.normal(0, 0.3, n)
X = np.column_stack([x1, x2])
brut = LinearRegression().fit(X, y)
norme = StandardScaler().fit(X)
aligne = LinearRegression().fit(norme.transform(X), y)
cb = np.round(brut.coef_, 3)
ca = np.round(aligne.coef_, 3)
print(f"[{cb[0]:.3f} {cb[1]:.3f}]")
print(f"[{ca[0]:.3f} {ca[1]:.3f}]")
```

La sortie est :

```
[1.945 0.020]
[1.875 1.898]
```

Avant, 1,945 contre 0,020 : on lirait que la première variable domine. Après, 1,875 contre 1,898 : les deux effets, mesurés en écarts-types, se valent. C'est bien la construction du jeu. La cible vaut environ 2 x₁ + 0,02 x₂, et x₂ est cent fois plus dispersée. Le produit est du même ordre. La standardisation ne change pas la prédiction, elle change la lecture.

## Ce que ça change en pratique

Le pipeline que vous mettrez derrière une API emporte ces transformations avec les coefficients. Vous les apprenez sur l'entraînement, vous les enregistrez, vous les rejouez à l'appel. Une moyenne recalculée sur le trafic du jour, une modalité inconnue codée au hasard, une colonne oubliée dans une autre unité : le modèle servi a dérivé sans que les poids aient bougé.

Le levier est donc de traiter la préparation comme une partie du modèle, pas comme un préambule jetable. Le cas où une standardisation n'est pas le bon geste : un modèle qui coupe sur des seuils, comme l'arbre du Chapitre 9, se moque souvent de l'échelle. La fuite, elle, ne se moque d'aucun modèle. Une statistique calculée avec la cible, ou avec les lignes que vous prétendez ne pas avoir vues, gonflera un chiffre que le Chapitre 7 apprendra à ne plus croire.

## Ce qu'il faut retenir

- Préparer une table, c'est figer une transformation apprise sur l'entraînement et la rejouer à l'appel.
- Une valeur manquante s'impute avec une statistique qui ne voit pas les lignes tenues à l'écart.
- Une catégorie devient une colonne par modalité, sans ordre inventé.
- La standardisation exprime chaque coefficient en écarts-types, et rend deux effets comparables.
- Une transformation qui utilise la cible, ou toute la table, n'est plus le modèle que l'on pourra servir.
