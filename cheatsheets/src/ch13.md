## Quand le *system prompt* devient trop long

- Depuis le ch. 7, un agent sert **trois métiers**, chacun avec sa procédure : analyser les **retards d'un client**, **contrôler une facture** (rapprochement commande + réception), préparer une **demande d'achat conforme** aux règles internes.
- Inscrites dans le *system prompt*, ces procédures seraient soumises au modèle **à chaque appel**, y compris pour l'état d'une commande.
  - Entrée plus longue → raisonnement dégradé à tâche égale (Levy et al., 2024) ; contenu sans rapport → **détourne** le modèle (Shi et al., 2023).
  - Texte retouché par trois métiers → **règles contradictoires** (acheteurs et comptables décrivent chacun le rapprochement → deux traitements d'une **réception partielle**).
- **Outils d'écriture** : proposés dès que l'utilisateur en a le droit, toute la conversation → le modèle peut préparer une approbation **sans la procédure de contrôle** sous les yeux.

## Qu'est-ce qu'un *skill* ?

- ***Skill*** : **savoir-faire nommé** que l'agent peut **charger** au cours d'une conversation. Trois éléments :
  - **Description courte** : à quoi il sert, dans quelles situations l'employer.
  - **Instructions** en langage naturel : étapes, règles, cas particuliers, forme attendue de la réponse.
  - **Ressources éventuelles** (barème, modèle de réponse) désignées par les instructions, consultées **au besoin**.
- Ensembles **composables** d'instructions, de code et de ressources, chargés à la demande, qui étendent les capacités de l'agent **sans réentraînement** (Xu et Yan, 2026). Emballe une **connaissance procédurale avec ses conditions d'application**, réutilisable d'une tâche à l'autre (Jiang et al., 2026). Précurseur : agent de jeu vidéo enrichissant une **bibliothèque de comportements en code exécutable** (Voyager, Wang et al., 2023).
- Fil rouge : **texte seulement**, rédigé et relu par des gens du métier (ch. 7 a exclu l'exécution de code produit par le modèle).
- Rédiger la description **comme celle d'un outil** (ch. 6) : nommer les demandes qui doivent déclencher le chargement, **dans les termes des utilisateurs**.
- Critères du ch. 11 : **provenance** = catalogue tenu par l'éditeur (auteur, périmètre, version) ; **durée de vie** = la conversation une fois chargé ; **confiance** = celle d'une **consigne** (le modèle **suit** la procédure ; il **cite** un document, se **méfie** d'un contenu tiers, ch. 14). Confiance sur la **manière de travailler**, jamais sur ce que l'agent **a le droit** de faire.

## À retenir — déclenchement

La **description décide du déclenchement**, le **contenu de l'utilité**. Le modèle choisit de charger en ne lisant **que la description** : une excellente procédure mal décrite peut **ne jamais être chargée**.

## Charger au moment utile (fig. 13-1)

- **Divulgation progressive** (ch. 6 et 9) appliquée aux consignes : **descriptions** de tous les *skills* accessibles en permanence (après le *system prompt*) → **corps** seulement une fois chargé → **ressources** lues seulement si la procédure y conduit.
- Fig. 13-1 : début de conversation = *system prompt* court + descriptions des *skills* + outils de lecture → après chargement du *skill* « contrôle de facture », s'ajoutent ses instructions + l'outil **« préparer l'approbation d'une facture »**, révélé avec lui (**seulement si** l'utilisateur a aussi le droit d'approuver) → si la procédure le demande : ressource du *skill* (barème).
- Chargement **par un outil** : le modèle reconnaît la description, demande le *skill* **par son nom** ; le ***harness*** vérifie qu'il est **dans le catalogue**, récupère le contenu, l'ajoute au contexte. Coût : **un cycle de plus** avant la première action utile.
- Chargement différé : **meilleure sélection** des *skills*, **légère hausse de latence** (Zhang et al., 2026).
- Échecs de déclenchement : répondre avec le savoir général, charger un *skill* **voisin**, en charger **plusieurs par précaution** → visibles dans les trajectoires **si le chargement est tracé**.
- Le contenu chargé doit **survivre à la compaction** (ch. 10) : un résumé approximatif ferait perdre des règles.

## *Skill*, consigne, outil, document (tableau 13-1)

| | Consigne permanente | *Skill* | Outil |
|---|---|---|---|
| Apporte | Règle valable pour toute demande | Procédure pour un type de tâche | Donnée ou opération |
| Contexte | À chaque appel | Description à chaque appel ; contenu après chargement | Définition à chaque appel ; résultat après exécution |
| **Qui l'applique** | Le modèle | Le modèle | **Le programme** |
| Exemple (fil rouge) | Annoncer un résultat partiel | Contrôler une facture par rapprochement | Interroger une source de données |

- Outil = **pouvoir** obtenir une donnée/faire une opération ; *skill* = **comment enchaîner** les opérations et selon quelles règles.
- Procédure du *skill* suivie par le modèle → **variabilité**. Règle à appliquer **à coup sûr** (exclusion, plafond, contrôle de droits) → **outil ou programme** (ch. 4). Le *skill* : **jugement** et **ordre des étapes**.
- **Document** (recherche, ch. 12) : information que l'agent **cite**, de n'importe quel contributeur. ***Skill*** : manière de travailler **prescrite**, autorité d'une consigne, **seul catalogue de l'éditeur**. Une procédure peut exister sous les deux formes (texte de référence cité + *skill* qui en tire la méthode).

## Révéler un outil avec son *skill*

- Le *skill* **déclare ses outils** ; le programme les ajoute à la liste visible **au chargement**.
- Moins de définitions dans le contexte (ch. 6) ; sélection préalable des outils → *prompt* allégé, meilleur choix (RAG-MCP, Gan et Sun, 2025). Surtout : **la procédure est dans le contexte avant que l'outil soit disponible**.
- Mise au point délicate : liste d'outils changeante → modifie le **début de la séquence**, peut **annuler le bénéfice du cache** ; toujours visibles : **outil de chargement** et **outils de lecture** ; un *skill* peut déclarer un outil **renommé ou retiré** ; **tous les chemins de chargement** doivent produire le même effet.
- **Révéler ≠ autoriser** : divulgation liée au *skill* **s'ajoute** à la restriction du ch. 7. Outil d'écriture présenté **ssi** l'utilisateur a le droit **ET** le *skill* est chargé.

## Précharger un *skill*

- L'application indique un *skill* à charger **avant le premier appel** → épargne le cycle de choix.
- **Mêmes contrôles** (appartenance au catalogue) ; raisonnable d'en accepter **un seul** (pour ne pas reconstituer un long texte permanent).
- Ne vaut que si le **signal est fiable** : à tort → occupe le contexte, oriente vers une procédure inadaptée, peut **rendre visibles des outils d'écriture** sans raison.

## Versionner et maintenir un catalogue

- Hors *system prompt*, le rapprochement de facture (acheteurs + comptables) n'existe **qu'en un exemplaire**.
- **Version** par *skill* : savoir quelle procédure a été suivie dans une conversation, **revenir** à la précédente si dégradation, **cacher** le contenu sans servir un texte périmé.
- Tester : demandes prévues → chargement ; demandes **voisines** → pas de chargement ; procédure → **bons appels** (ch. 15).
- Savoir **qui peut écrire** dans le catalogue : instructions malveillantes cachées dans un long *skill* ou un script référencé → **divulgation de données** (Schmotz et al., 2025) ; vulnérabilités dans une part notable des *skills* communautaires (Xu et Yan, 2026) ; risques de **chaîne d'approvisionnement** (Jiang et al., 2026). Catalogue interne relu et versionné : moins exposé, mais **relecture comparable au code**.

## Les choix de conception du fil rouge

- Catalogue de **3 *skills* versionnés** : « analyser les retards d'un client », « contrôler une facture par rapprochement », « préparer une demande d'achat conforme ».
- Chargement **par le modèle**, via un outil du *harness* qui **refuse tout *skill* hors catalogue** ; ni classifieur ni préchargement (pas de signal fiable).
- 2 outils d'écriture proposés **après chargement de leur *skill*** : sans droit d'approbation, l'utilisateur reçoit la procédure de contrôle, **l'outil d'approbation reste absent**.
- Coûts : « approuve cette facture » commence par **charger le contrôle** ; liste d'outils changeante → moins de **cache du début de séquence** (ch. 3) ; recherche documentaire (ch. 12) + écriture **sans protection contre l'injection de *prompt*** : un passage piégé peut orienter un brouillon que l'utilisateur confirmera (→ ch. 14).
## Pièges

- **Un *skill* ajoute une condition, n'en retire aucune** : le serveur d'outils **vérifie les droits à chaque exécution**, révélé ou non ; **confirmation par l'interface** toujours exigée pour toute écriture ; un *skill* déclarant un outil hors périmètre **ne l'ouvre pas**.
- Chemins à couvrir : *skill* **inaccessible accepté** par l'outil de chargement ; **préchargement contournant le filtre**.
- Filtrer aussi les ***prompts* et ressources** servis par un **serveur MCP** à côté de ses outils : les moins filtrés, ils entrent pourtant dans le contexte.
- **Ne jamais mettre en cache un échec de récupération** d'un *skill* : quelques secondes d'indisponibilité → absence durable, l'agent travaille sans procédure jusqu'à expiration, sans que personne le voie.
- **Zone d'incertitude** : mesure naissante. SkillsBench (Li et al., 2026) : gain moyen, ampleur variable selon configurations ; *skills* **ciblés > ensembles exhaustifs**. *Skills* **produits par l'agent** peuvent **dégrader** (Jiang et al., 2026). → mesurer chaque *skill* sur **vos** parcours.

## Critères

- ***Skill* ou outil ?** trancher par **« qui l'applique »** : jugement, ordre des étapes → *skill* (modèle) ; exclusion, plafond, contrôle de droits → **outil ou programme**.
- ***Skill* ou document ?** méthode prescrite, catalogue de l'éditeur → *skill* ; information citée, tout contributeur → document.
- ***System prompt* ou *skill* ?** procédures **longues et occasionnelles** → *skills* ; règles **courtes et permanentes** → *system prompt* (un chargement oublié les rendrait inopérantes).
- **Outil d'écriture visible** = **droit de l'utilisateur ∧ *skill* chargé** ; droits **revérifiés à l'exécution**.
- **Chargement** : décidé par le **programme** (classe la demande, classifieur à maintenir), le **modèle** (via outil, refus hors catalogue) ou l'**application** (préchargement : **un seul**, du catalogue, **signal fiable**).
- **Tests** : *skill* hors catalogue refusé ; *skill* chargé **présent après compaction** (section fixe).

## À retenir — cinq idées

1. Un *system prompt* qui accumule les procédures **pèse à chaque appel** et devient difficile à maintenir.
2. *Skill* = description + instructions + ressources ; **la description déclenche**.
3. Confiance **d'une consigne** ; règles sûres → **outil ou programme**.
4. Révéler l'outil d'écriture avec son *skill* place **la procédure avant l'action**, **sans étendre les droits**.
5. Un catalogue se **versionne, se teste et se relit comme du code**.
